## 2. ما أضيف

- `options_radar/signal_ledger.py` — مكتبة نقية (stdlib):
  - هوية OCC وتحقق تعارض الجهة/السترايك/التاريخ، ورفض العقود المعدلة.
  - ملف التسوية وآخر وقت تداول: SPX (AM) يتوقف يوم العمل السابق، SPXW وخيارات الأسهم/ETF الساعة 16:00 نيويورك. **أيام العطل ونصف اليوم غير منمذجة** (`half_day_not_modelled`).
  - تصنيف البيانات: `LIVE / DELAYED / RESEARCH_ONLY / STALE / UNAVAILABLE` فوق `execution_confidence.assess_execution_quote`. آخر صفقة Last وحدها = UNAVAILABLE.
  - معرّف ثابت `signal_id` = SHA-256 لـ (OCC + جلسة نيويورك + نسخة السياسة) ← توصية واحدة لكل عقد في الجلسة.
  - قرار: `CONFIRMED` فقط إذا وافقت V11 **و** كانت التسعيرة LIVE. غير ذلك WATCH (بلا Telegram) أو رفض مع الأسباب.
  - آلة الحالات: `CREATED → WATCHING → ENTRY_ELIGIBLE → PAPER_ACTIVE → TARGET_1/2/3` والبدائل `STOPPED / INVALIDATED / EXPIRED / DATA_STALE / AMBIGUOUS / CLOSED`.
  - سجل أحداث إلحاقي، وتجاهل أي تسعيرة قبل وقت النشر أو مكررة أو خارج الترتيب.
- `scripts/run_signal_ledger.py` — دورة واحدة: يتبنّى الرسائل التي أرسلها المرسل الحالي (لا مرسل مكرر)، يراقب من صفوف الحمولة نفسها (لا مصدر بيانات جديد)، يعدّل رسالة Telegram الأصلية ويرد باختصار عند الهدف/الوقف/الإلغاء/التوقف، ويكتب السجل الخاص وملف الصفحة العام.
- `public/signal.html|js|css` + إعادة توجيه `/options/signal/:id` في `vercel.json`.
- اختبارات: `tests/test_signal_ledger.py`، `tests/test_run_signal_ledger.py`، `tests/signal_page.cjs`، وخطوة CI في `test.yml`.

## 3. قواعد التنفيذ الورقي (سياسة `LEDGER_POLICY_V1` — افتراضات صريحة غير مُعايرة)

| أدنى عائد/مخاطرة للهدف الأول بعد التكاليف | 0.8 | |

## 4. الترخيص والعرض العام

الصفحة العامة **تحجب** أسعار العقد ومستوياته وشموعه ما لم يكن مصدر التسعيرة في قائمة يسجلها المالك صراحة (`SIGNAL_PUBLIC_DISPLAY_SOURCES`) **وخارج** العائلات المغلقة في `public_guard`. المصدر المجهول محجوب. عند الحجب تظهر `DATA UNAVAILABLE` مع السبب، ويبقى السجل الزمني للحالات ظاهرًا.

الشموع تُبنى من منتصف Bid/Ask للقطات المؤرخة (دقيقة لكل شمعة) ومُعلَن ذلك على الصفحة؛ ليست صفقات، والحجم غير متاح منها. شارت السهم رابط منفصل ولا يُعرض كشارت للعقد.

## 5. الربط التشغيلي ومفاتيح المالك

**الربط (منفّذ):**

| الملف | الكاتب الوحيد | المسار |
|---|---|---|
| `data/live/signal_ledger.json` (خاص: معرّفات الرسائل) | `options-contract-radar.yml` → `run_signal_ledger.py` | Artifact `signal-ledger-state` فقط، لا يُنشر |
| `public/data/signal_ledger.json` (عام بعد الحجب) | نفس الخطوة | Artifact، ثم ينسخه `options-radar.yml` إلى `bot-state/runtime` عبر `runtime_state_vault` مع حارس الترخيص (`generic`) |

خطوة السجل `continue-on-error`، فلا يمكن أن توقف الرادار. تعمل فقط في الجلسة الأمريكية النظامية، مثل الرادار.

**مفاتيح المالك (Repository variables، كلها مطفأة افتراضيًا):**
1. أولًا: تفعيل مزود خيارات مرخّص يعطي Bid/Ask بتوقيت مطلق. بدونه لن تخرج أي توصية CONFIRMED؛ هذا سلوك صحيح.
2. `SIGNAL_LEDGER_LINKS=1`: يضيف رابط الصفحة إلى رسالة التوصية الجديدة.
3. `SIGNAL_LEDGER_TELEGRAM=1`: يفعّل تعديل الرسالة الأصلية والردود عند الهدف/الوقف/الإلغاء/التوقف.
4. `SIGNAL_PUBLIC_DISPLAY_SOURCES`: اختياري، فقط بعد توثيق حق النشر العام كتابيًا.

**قيد التوقيت:** GitHub Actions لا يضمن تشغيلًا كل دقيقة؛ المراقبة تتم كل دورة للمنسق، وأي فجوة تظهر `DATA_STALE` ولا تُخفى. نجاح Workflow لا يعني أن المراقبة كانت متصلة.
