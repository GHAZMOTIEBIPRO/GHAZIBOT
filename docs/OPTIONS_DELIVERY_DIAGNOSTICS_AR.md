# BLACK BOX Ω — شرح تشغيل العقود والتنبيهات

## ما الذي تغير؟

تم إصلاح **وضوح التشغيل** دون تغيير أسعار العقود أو قواعد إنتاج التوصيات.

- أثناء إغلاق بورصة نيويورك، يستمر إنشاء ملف تشخيص `options-e2e-evidence` بنتيجة `MARKET_CLOSED`. نجاح Workflow في هذه الحالة **لا يعني أن العقود قد فُحصت أو أن رسالة أُرسلت**.
- أثناء جلسة التداول، يميز التقرير بين: `PAYLOAD_MISSING` و`NO_EXECUTION_GRADE_QUOTES` و`NO_CANDIDATES` و`SENDER_BLOCKED` و`NO_REPORTED_SEND`.
- لا يعتمد تشخيص الرسائل الحالية على العدد المخزن من أيام سابقة؛ يظهر `delivery_state_current_scan=false` إذا لم يرتبط توقيت سجل المرسل بنتيجة المسح الأخيرة. حقول IDs في الحالة قد تكون تاريخية.
- يرسل `radar-health.yml` إشعارًا توضيحيًا واحدًا كحد أقصى في كل يوم تداول أمريكي عندما يبقى مسار الأوبشن `DEGRADED` دون عروض أسعار تنفيذية موثوقة. ويرسل أيضًا عند تغير وضع مصادر الأسعار حتى إن بقيت الحالة العامة `DEGRADED`.
- هذه إشعارات **صحة مصادر** وليست توصيات تداول؛ تبقى شروط `v11_gate`، وحظر الأسعار المتأخرة، وعدم إرسال إشارات `WAIT` كما هي.

## أين أجد الإثبات؟

1. افتح GitHub → Actions → **BLACK BOX Omega Options Contract Radar** → آخر تشغيل.
2. افتح artifact `options-e2e-evidence` ثم `e2e_delivery_evidence.json`.
3. اقرأ `diagnosis.reason_code` و`diagnosis.note_ar` و`telegram.blocked_reason`.
4. للتنبيهات الصحية، افتح **BLACK BOX Omega Radar Health** وتحقق من أن جلسة XNYS كانت مفتوحة وأن وجهة Telegram جاهزة.

## حقائق مهمة

- نجاح `Tests` أو `Vercel` يثبت نجاح تلك الخطوات فقط، وليس إرسال توصية.
- `sendMessage` بإقرار من Telegram يثبت قبول المنصة للرسالة، وليس أنها ظهرت على شاشة الهاتف.
- الوصول إلى بيانات Options تنفيذية يحتاج مزود بيانات يملك صلاحية وتوقيت bid/ask موثوقًا؛ لا يتحول Yahoo أو GammaGrid إلى مصدر لحظي بمجرد تعديل اسم المصدر.
- رفض SEC/OCC برمز 403 لا يعالج بتجاوز الحظر؛ نلتزم بسياسة المعدل وUser-Agent ومصادر fallback الرسمية.
- `GammaGrid` في PR #218 قارئ JSON بحثي اختياري، وليس تكاملًا تلقائيًا مع OAuth MCP.
