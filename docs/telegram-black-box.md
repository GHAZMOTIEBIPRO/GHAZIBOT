# BLACK BOX Ω — نظام تيليجرام الآلي

## الفكرة الجديدة

تيليجرام لم يعد يعتمد على كل محرك يرسل رسالة بطريقته.

البنية أصبحت:

`مصادر السوق -> الرادار السريع + Ω + Delta/Effective Float -> محلل مسببات الانفجار -> مرسل عربي موحد -> Telegram`

الهدف أن تصل الرسالة للمستخدم بهذا الترتيب:

1. ماذا يحدث الآن؟
2. ما المسبب الأقوى للحركة؟
3. ما مسببات الانفجار الأخرى المتزامنة؟
4. ما الذي يؤكد استمرار الحركة؟
5. ما الذي يضعف الفكرة أو يبطلها؟
6. هل التوقيت مبكر أم بدأ يدخل في المطاردة؟

## مسببات الانفجار التي يراقبها البوت

- خبر أو محفز جوهري موثق وجودته وأهميته.
- حالة إعادة التسعير بعد الخبر.
- نقص المعروض وضيق الأسهم الحرة.
- تقدير الـEffective Float وSupply Vacuum.
- تسارع الحجم النسبي.
- تسارع الحجم بين فحصين متتاليين.
- دوران السيولة مقارنة بالقيمة السوقية.
- مشاركة الطلب والسيولة.
- بداية إعادة التسعير في السعر نفسه.
- الاختراق الفني عندما يكون موجودًا.
- دعم هيكل عقود الخيارات كعامل مساعد، وليس شرطًا وحيدًا.
- تغير المعلومات بين فحص وآخر.
- إيقافات التداول عندما تكون مرتبطة بالسهم المرشح.

## شكل الرسالة

العناوين والتفسير بالعربية. الرمز والسعر واسم المصدر قد تبقى بصيغتها الأصلية لأنها بيانات سوق.

الرسالة تعرض:

- الحالة: ضغط يتكوّن / قبل الانفجار / اشتعال مبكر / انفجار سعري.
- قوة الإشارة كترتيب داخلي، وليست احتمال نجاح.
- المسبب الأقوى.
- مسببات الانفجار مرتبة حسب الأهمية.
- قراءة مختصرة من BLACK BOX Ω.
- شرط التأكيد.
- المخاطر.
- نقطة التفعيل ومستوى الإبطال إن توفرا.
- تقييم التوقيت ومنع المطاردة.

## التشغيل الآلي بدون تدخل المستخدم

### 1. الرادار السريع

Workflow:

`BLACK BOX Omega Fast Explosion Radar`

يفحص السوق الأمريكي كاملًا خلال أيام التداول على فترات من 10 إلى 20 دقيقة حسب نافذة السوق.

هذا المسار أصبح **جامع بيانات فقط** ولا يرسل رسائل مباشرة. يرفع ناتج الفحص كـGitHub Actions Artifact حتى يستهلكه المرسل الموحد.

### 2. التحليل العميق

Workflow الأساسي يحدث `public/data/latest.json` وفيه طبقات Ω والمحفزات والمخاطر والفرص.

### 3. محرك Delta والـEffective Float

قبل كل إرسال موحد يتم تحديث:

- `data/live/delta_history.json`
- `data/live/delta_signals.json`

وذلك لرصد ما تغير بين الفحوص بدل الاعتماد على صورة لحظية فقط.

### 4. المرسل العربي الموحد

الملف:

`options_radar/arabic_explosion_notifier.py`

يجمع الرادار السريع والتحليل العميق وDelta، ثم يختار سبب الحركة الحقيقي الأقوى ويمنع تكرار نفس التنبيه.

حالته تحفظ في:

`data/live/arabic_explosion_alert_state.json`

### 5. الربط الدائم بتيليجرام

المطلوب الأساسي:

- `TELEGRAM_BOT_TOKEN`

`TELEGRAM_CHAT_ID` يمكن أن يكون Secret ثابتًا، لكن النظام قادر أيضًا على تعلم المحادثة من `/start` ثم حفظ الوجهة مشفرة داخل Artifact خاص بـGitHub Actions وإعادة استخدامها تلقائيًا.

## متغيرات الضبط الرئيسية

- `OMEGA_ARABIC_MIN_SCORE` — الحد الأدنى الافتراضي 72.
- `OMEGA_ARABIC_MAX_ALERTS` — الحد الأعلى الافتراضي 3 رسائل لكل تشغيل.
- `OMEGA_ARABIC_MAX_DILUTION` — يمنع الحالات ذات خطر زيادة المعروض المرتفع جدًا.
- `OMEGA_ARABIC_MAX_CHASE_PCT` — يمنع إرسال سهم أصبح ممتدًا سعريًا.
- `OMEGA_ARABIC_STATUS_INTERVAL_HOURS` — تقرير صحة دوري عند عدم وجود فرصة جديدة.

## منع الإزعاج

لا يعاد إرسال نفس السهم لمجرد أن الفحص تكرر.

يعاد التنبيه فقط عند تغير مهم مثل:

- انتقال الحالة إلى مرحلة أعلى.
- ارتفاع قوة الإشارة بشكل جوهري.
- ظهور مسبب انفجار جديد أقوى.
- تغير الخبر أو المحفز المسيطر.

## الاستقلالية التشغيلية

بعد ضبط Telegram Token وتعلم Chat ID مرة واحدة، التشغيل لا يحتاج زر تشغيل أو أمر يدوي من المستخدم.

GitHub Actions يتولى:

- الجدولة.
- جمع البيانات.
- استعادة ذاكرة الفحص السابقة.
- تحليل Delta.
- تحليل مسببات الانفجار.
- إرسال الرسالة.
- حفظ حالة منع التكرار.
- حفظ Chat ID المشفر.
- إعادة المحاولة في الفحص التالي إذا تعطل تشغيل سابق.

وعند فشل مسار الإرسال نفسه بعد نجاح ربط تيليجرام، يحاول الـWorkflow إرسال رسالة نظام عربية تفيد بوجود عطل.

## ما يحتاجه النظام ليكون أقوى

النسخة الأساسية تعمل بالمصادر المجانية الموجودة في المشروع. ولزيادة جودة الاكتشاف يمكن إضافة مفاتيح مصادر اختيارية مثل:

- `FINNHUB_API_KEY`
- `ALPHA_VANTAGE_API_KEY`

هذه ليست شرطًا لبقاء GitHub Actions يعمل، لكنها توسع تغطية الأخبار والبيانات عندما تكون الخدمات متاحة.

## ملاحظة منهجية

كل الدرجات في البوت هي درجات ترتيب وإشارات داخلية وليست احتمالًا إحصائيًا مضمونًا للربح أو توصية شراء.
