# BLACK BOX Ω — جسر سنايبر إلى البوت

## الهدف

يربط مؤشر **سنايبر** في TradingView مع بوت BLACK BOX على Telegram، دون تنفيذ أوامر تداول آلية.

المسار:

`TradingView / سنايبر -> HTTPS webhook -> BLACK BOX -> Telegram -> فحص عقد متوافق + خبر/محفز -> تعديل نفس الرسالة`

ويظل مسار **Options Contract Radar** المستقل عاملًا كل 15 دقيقة لاكتشاف العقود حتى بدون إشارة سنايبر.

## حماية الـWebhook

يدعم الخادم وضعين:

1. **مفتاح مسار** — الموصى به: اضبط `SNIPER_WEBHOOK_SECRET` ثم استخدم:
   `https://HOST/webhooks/sniper/<secret>`
2. **بدون مفتاح إضافي**: استخدم `https://HOST/webhooks/sniper`، وعندها يقبل الخادم فقط عناوين IP المعلنة رسميًا من TradingView للـwebhooks.

يفضل تشغيل مفتاح المسار في الإنتاج لأن بعض طبقات الـproxy قد تختلف في طريقة تمرير عنوان العميل. لا تضع Telegram token أو مفاتيح مزودي السوق داخل رسالة TradingView.

## متغيرات التشغيل

- `TELEGRAM_BOT_TOKEN` — موجود أصلًا في BLACK BOX.
- `TELEGRAM_CHAT_ID` — موجود أصلًا أو يحلّه نظام الاتصال الحالي.
- `SNIPER_WEBHOOK_SECRET` — اختياري لكنه موصى به بقوة.
- `SNIPER_ENRICH_ENABLED=true` — يفحص العقد والخبر بعد وصول الإشارة ويعدل نفس رسالة Telegram.
- `SNIPER_MAX_EVENT_AGE_SECONDS=900` — يرفض الإشارة القديمة.
- `SNIPER_WEBHOOK_DEDUPE_TTL_SECONDS=86400` — يمنع تكرار نفس الإشارة.
- `NEWS_ALERT_MIN_ABS_SCORE=15` — أقل أثر خبري خام لإرسال تنبيه مستقل.
- `NEWS_ALERT_MAX_PER_RUN=5` — حد الرسائل الخبرية في التشغيل الواحد.

## إعداد TradingView

في سنايبر:

- `تفعيل تنبيهات سنايبر الديناميكية = تشغيل`
- `رسالة JSON للبوت / Webhook = تشغيل`

ثم أنشئ Alert واحدًا على **Any alert() function call**، واختر Webhook URL، واجعل التنبيه يعمل عند إغلاق الشمعة. Pine نفسه يكوّن JSON ديناميكيًا ويضع فيه الاتجاه، الجودة، الدخول، الإلغاء، الأهداف، الأفق، الفريم، المحرك، وحالة السوق.

## العقود

بعد وصول إشارة سنايبر، يعمل الفحص في الخلفية ويبحث عن عقد من **نفس اتجاه الإشارة**:

- يومي: 0–2 DTE
- أسبوعي: 3–10 DTE
- شهري: 14–45 DTE
- مخصص: 7–45 DTE

الفحص يحافظ على تصنيف مصدر البيانات وحداثته ولا يحول بيانات مجانية/Indicative إلى OPRA إنتاجية بالاسم فقط.

وبشكل مستقل عن سنايبر، يبقى `options-contract-radar.yml` مسؤولًا عن رصد عقود CALL/PUT الصارمة، السيولة، السبريد، Delta، DTE، Vol/OI، سياق Gamma، والتوافق بين المزودين.

## الأخبار

Workflow مستقل: `.github/workflows/sniper-news-watch.yml`

يعمل آليًا أيام السوق كل 15 دقيقة تقريبًا. بدل حصر الأخبار في قائمة أسهم ثابتة، يبني عالم التغطية من **دليل OCC الرسمي للرموز القابلة للأوبشن**، ثم يمر عليها على دفعات متعاقبة مع إبقاء قائمة السيولة/المفضلة في كل تشغيل.

المصادر الحالية:

- SEC EDGAR — المصدر الرسمي الأول لإفصاحات الشركات.
- openFDA / Drugs@FDA — للأحداث الدوائية والتنظيمية.
- Yahoo Finance News — طبقة أخبار ثانوية وليست دليلًا رسميًا مستقلًا.

بهذا الأسلوب تتوسع التغطية إلى الشركات التي لديها عقود خيارات بدل مراقبة بضعة رموز فقط، مع احترام حدود GitHub Actions ومصادر البيانات. ولا يرسل النظام إلا الأحداث ذات أثر خام جوهري مع dedupe دائم بين تشغيلات GitHub Actions.

## مبدأ عدم الإزعاج

- إشارة سنايبر = رسالة واحدة.
- إذا وجد العقد أو الخبر بعد الإشارة، يتم **تعديل نفس الرسالة** بدل إرسال رسائل إضافية.
- رادار العقود المستقل يحتفظ بسياسة رسالة واحدة لكل رمز/اتجاه مع dedupe الحالية.
- الأخبار المستقلة تستخدم بصمة خبرية لمنع تكرار العنوان نفسه عبر التشغيلات.

## الحدود

TradingView يطلب استجابة webhook سريعة؛ لذلك الخادم يعيد `202 Accepted` مباشرة ثم ينفذ Telegram وفحص العقد/الخبر في worker منفصل. هذا يمنع مهلة الثلاث ثوانٍ من تعطيل التنبيه.

GitHub Actions مناسب للمسح المجدول، لكنه ليس stream لحظيًا. العقود اللحظية الحقيقية وجودة التنفيذ تعتمد على مزود البيانات ودرجة الاستحقاق المتاحة للحساب؛ النظام لا يعيد تسمية بيانات متأخرة أو indicative على أنها OPRA حية.
