# Daily 15-minute Opening Fibonacci Telegram scanner

## ماذا يفعل؟
- عند إغلاق شمعة 09:30–09:45 نيويورك، ينتظر تأخر بيانات المزود؛ فحص يومي مبدئي 10:27 أو 10:42 بتوقيت نيويورك.
- يجلب شموع 5 دقائق من Alpaca من خلال الخيارات والضوابط الموجودة مسبقًا في المستودع، ويبني شمعة الافتتاح من 3 شموع متجاورة ومكتملة فقط.
- يمسح الرموز المُدرجة في data/universe.txt (بحد أقصى 150 افتراضيًا، وحد برمجي أقصى 300). يضع لكل سهم: مراقبة كول / مراقبة بوت / انتظار / بيانات ناقصة.
- لا ينشر بيانات Alpaca في GitHub أو موقع عام، ولا ينشرها في قنوات Telegram. الرسالة للمالك فقط، وبعد إجازة سياسة حقوق المصدر والتحقق من أن Telegram private chat.
- يخزن فقط تاريخ آخر إرسال ناجح في فرع bot-state، لمنع التكرار. التشغيل اليدوي يبدأ بوضعيّة dry-run.
- يعرض حتى خمس فرص مفصلة ويصنف بقية الرموز في ملخص واحد؛ لا يخترع فرصة عند غياب الإشارة أو البيانات.

## متطلبات تفعيل الإرسال من GitHub
- الأسرار: ALPACA_API_KEY وALPACA_SECRET_KEY وTELEGRAM_BOT_TOKEN وTELEGRAM_OWNER_CHAT_ID (أو تفعيل fallback مع TELEGRAM_OWNER_USERNAME).
- متغيرات إقرار المالك بعد قراءة شروط المزود: ALPACA_INTERNAL_DATA_USE_AUTHORIZED=true وALPACA_PRIVATE_ALERTS_AUTHORIZED=true.
- يستفيد من البنية القائمة في options_radar/bar_providers.py وoutput_policy.py وscripts/telegram_transport.py.
- إذا لم تتحقق صلاحيات المصدر أو خصوصية الوجهة يمتنع عن الإرسال. GitHub Cron جدولة best-effort وليست ضمان وصول كل يوم.

## حدود مهمة
- شموع المصدر متأخرة 16 دقيقة على الأقل. WATCH_CALL / WATCH_PUT هي مراقبة بحثية، لا أسعار تنفيذ أو عقود أوبشن.
- يتطلب الإشارة إغلاق شمعتين متتاليتين خارج نطاق الافتتاح، وعائدًا مستهدفًا/مخاطرة مناسبًا قبل مراقبة الصفقة.
- "كل الشركات" هنا تعني كامل قائمة المراقبة المحددة في المشروع، وليس جميع آلاف الأسهم الأمريكية. يمكن توسيع القائمة ضمن حقوق المزود والميزانية.
- لا ينفذ أوامر سوق. لا تأكيد لعائد أو احتمال ربح.


## فحص التشغيل الحقيقي (Preflight)
من GitHub Actions اختر:
- Workflow: \`GHAZI RADAR - Daily Opening Fibonacci (owner private)\`.
- Run workflow: \`preflight=true\` (يمكن تشغيله يوم السبت).
- علامة \`PREFLIGHT_READY\` تثبت صلاحية الوصول إلى **3 شموع SIP مكتملة من آخر جلسة**، والتحقق من محادثة Telegram الخاصة وصلاحيات مصدر البيانات.
- لا يرسل preflight أي رسالة. \`PREFLIGHT_READY\` لا يثبت عمل الجدولة أو توصيل الرسالة اليومية؛ أول دليل لذلك هو سجل إرسال \`DELIVERED\` في يوم التداول.
- بعد يوم التداول، تأكد من أن وضع التشغيل نجح ومن استلام الرسالة. GitHub Actions Cron ليس ضمانًا لحظة بلحظة.

## تحسينات جودة السوق
- ابتداءً من طبقة التصفية الجديدة، لا يصدر WATCH_CALL أو WATCH_PUT من بيانات IEX وحدها: IEX مصدر تداول جزئي؛ يستخدم النظام بيانات SIP التاريخية المكتملة، وإلا يرجع إلى حالة WAIT/NO_DATA بأمان.
- حد سيولة افتتاح تقديري: \`OPENING_FIB_MIN_OPENING_NOTIONAL\` بوحدة دولار، الافتراضي 1000000. قيمته عبارة عن \`متوسط نطاق الافتتاح × مجموع حجم الشموع الثلاث\`؛ ليس قيمة تنفيذ فعلية ولا ضمان السيولة في عقود الخيارات.
- كل سهـم بلا ثلاث شموع 5 دقائق مكتملة، أو بخطأ بيانات، يبقى NO_DATA.
- لا تجزم تسمية CALL/PUT بوجود عقد خيار قابل للتداول، ولا تخمن سعر عقد أو دفتر أوامر أو Gamma.
- \`OPENING_FIB_MAX_SYMBOLS\` الافتراضي 150 بحد 300. القائمة الحالية 114 رمزًا تقريبًا؛ جميع الشركات الأمريكية أكبر من هذا بكثير وتتطلب ترخيصًا وحصص API أعلى.
